# 对话记录 02 — 文本标签方案设计与实现

**日期**：2026-05-15  
**参与方**：用户 + Claude Code  
**主题**：设计并实现"固定主标签 + 动态子标签"的文本标签抽取方案

---

## 关键讨论节选

### 1. 方案选型

**用户**：针对用户问卷的文本回答，利用大语言模型自动提取用户标签，同时解决'标签过于稀疏、缺乏统一体系'的问题

**Claude** 提出 4 种方案：
- 方案一：纯关键词匹配（快但僵化）
- 方案二：纯开放 LLM 输出（灵活但碎片）
- 方案三：固定主标签 + 半开放子标签（平衡点）
- 方案四：Embedding 聚类（冷启动不可用）

**用户** 选择方案三。

---

### 2. 标签树设计反馈

**用户**（via `主标签+子标签方案.txt`）：

> Q22 的"散步闲逛"和"深度交流"存在语义重叠。真实应用里会遇到"吃饭顺便聊聊""散步+聊天""咖啡聊天"。如果「聊天」是主标签，会抢占所有场景的标签归属。建议加两个"互动方式标签"（横切维度）。

**结论**：聊天/交流从场景标签中移除，改为 interaction_mode 横切维度：
- `"河边走走聊聊"` → 散步闲逛 + 强互动
- `"喝咖啡聊天"` → 美食社交 + 强互动
- `"图书馆自习"` → 学习共处 + 弱互动

---

### 3. Q24 缺失维度

**用户**：对于 Q24 补充要求，缺一个非常高频的维度——价值观/三观

**补充**：新增"价值观与人生观"主标签（9 个预设子标签），Q24 从 6 类扩充为 7 类。

---

### 4. 实现策略

**确定的集成方式**：
- 标签抽取在 `generatePersonaCardFromSource` 中与 LLM 文案并行调用
- 输出结构挂在 `PersonaCardPayload.textTags` 可选字段
- 无 API Key 时用关键词匹配降级，确保离线演示可用
- 合约测试覆盖标签树稳定性 + 输出形状校验
