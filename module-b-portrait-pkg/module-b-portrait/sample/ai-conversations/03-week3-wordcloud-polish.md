# Week 3 — 兴趣词云产品级打磨

> 工具：`claude -p` 一次性问答，记录于 2026-04 月底

## 我问

老师，我在做兴趣词云组件，从 `series.type=graph` + `layout=force` 改用 `echarts-wordcloud` 插件。想问三个问题：(1) `sizeRange` 应该固定 [12, 42] 吗？默认 [12, 60] 会让单个标签占半屏。(2) 中文要不要旋转？`rotationRange:[-90, 90]` 能增加密度但中文旋转很难读。(3) 要加 6 个分类筛选 chip 吗？增加 UI 但可以按类浏览。

## AI 答

很好的问题，三条都给具体配置：

**(1) sizeRange 固定 [12, 42]，配合 `shrinkToFit:true` + `drawOutOfBound:false`**。理由：易读性 > 密度。默认 [12, 60] 在小 portrait（≤ 10 个 tag）下会让最大权重 tag 吃掉半屏，把次大 tag 挤到 12px 边缘。下限 12 是中文可读底线（小于这个老年用户 / 移动端会眯眼）；上限 42 是单 tag 不会喧宾夺主的天花板。`shrinkToFit:true` 让插件在画不下时自动缩比例而不是 drop tag，保证用户看到全部兴趣。

**(2) 中文坚决不旋转**。`rotationRange: [0, 0]`，`rotationStep: 0`。中文是方块字，竖读 / 90° 旋读体验糟糕——汉字单字符没有英文那种 baseline 对齐美感，旋转后用户会下意识倾头。代价是密度下降 ~15%，但一份"读得了的稀疏图"比一份"看着炫但需要扭脖子的稠密图"产品价值高得多。

**(3) 加分类筛选 chip，6 个是甜区**。加一个「全部」reset chip 在最前；激活态 chip 用对应分类色；右上角显示 `{filtered}/{total} 个标签`。少于 4 个分类显得 UI 浪费，多于 8 个用户开始忘掉哪个是哪个，6 个正好。

→ 落地：你贴的 `[12, 42]` + `[0,0]` + `gridSize:6` 应该能跑出干净布局。验收清单：3 用户 portrait（10/30/50 tag 各 1 个）下看是否都不溢出 + 是否最小字号 ≥ 12。
