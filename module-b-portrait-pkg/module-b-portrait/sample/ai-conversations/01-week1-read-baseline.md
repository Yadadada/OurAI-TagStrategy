# Week 1 — 读懂 personaCard.ts

> 工具：`claude -p` 一次性问答，记录于 2026-04 中旬

## 我问

老师，有个问题。`src/personaCard.ts:420` `buildUserVector` 计算 15 个维度，SECURITY 维度用 `(8-q04, 8-q08)` 反向计分，但我注意到 q04 好像也出现在 EMPATHY 维度里 (`avg(q02, q04)`)？这是故意的重复计数吗？另外，L/M/H 量化把 7 级 Likert 压缩到 3 个等级，这样丢失了很多精度，为什么要这样设计？最后，为了获得优秀，应该新增问卷维度还是改进现有流程？

## AI 答

好问题，分三点回。

**(1) q04 的双重出现是故意的，但代价你要意识到**。q04 是"对方不及时回复时我会胡思乱想"——它既测**焦虑型不安全**（→ SECURITY 反向），也测**对对方信号的高敏感**（→ EMPATHY 正向）。从心理学构念上 q04 确实多面向，但工程上这等于在 15 维向量里悄悄给 q04 双倍权重。如果你要做"加新维度"的进阶，注意不要再让 q04 再被第三次计入，否则会进一步歪斜。

**(2) L/M/H 量化是鲁棒性 × 信噪比的权衡，不是丢精度的 bug**。Likert 的"5 vs 6"区分对自评噪声很大（同一人不同天可能就差 1 分），但"L vs H"几乎不会被噪声反转。L1 距离在 3 桶上比在 7 桶上更稳定，且 25 类型库的 pattern 是 L/M/H 写的——量化是为了**让用户和类型库在同一表示空间里**。

**(3) 优秀提交建议加新维度，不要改 vendored 算法本体**。具体推荐：**依恋风格子量表（焦虑/回避两轴）**。当前的 SECURITY 维度混淆了焦虑（q04/q08 偏向）和回避（q01/q12 偏向）两个独立构念——一个 dismissive-avoidant 用户和一个 secure 用户在 SECURITY 维上都可能拿到 H，但他们在恋爱行为上完全不同。把依恋抽成独立的两轴（甚至四象限），既能补盲区，又**不需要改 personaCard.ts 本体**——挂在 portrait extension 里就行，不破坏契约。
