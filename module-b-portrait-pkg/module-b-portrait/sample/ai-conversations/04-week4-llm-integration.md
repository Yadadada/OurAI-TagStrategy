# Week 4 — LLM 集成与答辩准备

> 工具：`claude -p` 一次性问答，记录于 2026-05 第一周

## 我问

老师好，我在做第四周的课程作业，集成了 `claude -p --model haiku` 来生成个性化的 80 字中文人格故事。有三个问题：(1) API 调用延迟约 30 秒，用户会不会觉得页面卡住了？应该用什么 UX 模式提示等待？(2) 当 claude 不可用时，应该返回 503 错误还是始终返回 200 但加 `source: fallback` 字段标记为降级？我倾向后者，但担心这样无法有效监控错误。(3) 我的 5 样本评测分布偏斜（3 焦虑 + 2 矛盾，0 安全、0 回避），对答辩报告影响大吗？

## AI 答

三条都给具体建议：

**(1) UX：明示 + 真进度，不要假流式**。在按钮 label 里标注「约 20-40s」让用户在点击前就有心理预期，点击后立刻显示「生成中…(haiku 约 20-40s)」配合 disabled 状态。**绝对不要做 fake streaming**——那是骗用户，破坏信任。乐观预览（preset 文案先显示然后被 LLM 结果替换）对课程作业过度工程，性价比低。一句话：**让用户知道你在等什么，等多久，然后老老实实等**。

**(2) 始终 200 + source 字段是正确的产品设计**。理由：用户永远能看到完整人格卡，体验不破。但这跟监控不矛盾——把 fallback 事件写到日志（reason、latencyMs、claude 版本），生产环境再加一个 `/metrics` endpoint 统计 fallback 率。课程作业只需要原则对：**降级不报错，但留下可观察的信号**。HTTP 5xx 是给"调用方需要知道并重试"的场景，LLM 故障对用户来说不是这种场景。

**(3) 5 样本偏斜是真实 limitation，写进 EXPERIMENTS.md**。偏斜的根源是 fixture 本身焦虑占 51.8%，你按 stride=100 抽 5 个就是它的镜像。改进路径：**分层抽样**——4 类依恋型各拿 3 条 + 各 MBTI 字母各覆盖一次，~12-16 条最低体面，~30 条才能说"定量结论"。在答辩里把它定位为"future work"，不要藏。同时配 1-5 分人工评分（你 + 同学 1 个独立打分），内部一致性 κ 也是加分项。

→ 落地清单：button label `约 20-40s` ✅；API 永远 200 ✅；EXPERIMENTS.md 写明 N=5 是示意性而非定量 ✅。
