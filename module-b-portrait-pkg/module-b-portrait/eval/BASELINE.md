- 主标签准确率提升有限（+0~5pp），longtail 网络用语仍是硬骨头
- 推测下一步：**Baseline #3 加 CoT** 让 LLM"先解释词义再选标签"，可能比单纯 few-shot 更管用，因为它让 LLM 显式推理"中央空调=对很多人都暖=不专一=不忠诚"这个语义链

- 副作用：互动维度准确率下降、子标签命中率回落，是注意力分散的代价

**PPT 叙事关键**：
- 三方法结果对比清晰：#4（零样本）、#2（few-shot）、#3（+CoT）
- 每种方法解决的问题不同：few-shot 教格式、CoT 教推理
- 没有银弹：每种方法都有副作用（few-shot 引入风格偏移、CoT 分散注意力）
- 工程选型建议：**生产环境推荐 #2（few-shot 不带 CoT）**——综合表现最稳健，延迟最低；CoT 只在已知 longtail 集中的字段开启

## 三维对比：精度 × 速度 × 成本（2026-05-31 重跑带 token 计量）

项目负责人方向 3 原话："**精度、速度、成本怎么取舍**"。原始三个 baseline 只记录了精度+速度两个维度，本节用同一份代码（在 `textTagExtractor.ts` 的 `callTagLlm` 中捕获 OpenAI 兼容 `usage` 字段）重跑了三组实验，补齐第三轴 = token 成本。

### 原始数字（244 条评测集，gpt-4.1）

| 方法 | 整体主标签准确率 | 平均耗时 | 平均 tok/样本 | prompt tok | completion tok |
|---|---|---|---|---|---|
| **#4 零样本** | **97.5%** | **1464ms** | **732** | 678 | 54 |
| **#2 +few-shot** | 96.7% | 1603ms | 1036 (+41%) | 963 | 74 |
| **#3 +few-shot+CoT** | **97.5%** | 1573ms | **1154 (+58%)** | 1084 | 70 |

> 注：#2 整体准确率 96.7% 与早先记录的 97.1% 差 0.4pp，属 LLM 单次随机性，不影响主结论。

### 关键发现

1. **零样本不是最贵的——它最便宜**。仅 732 tok/样本，反而精度和 #3 并列最高（97.5%）。
2. **few-shot 的成本不在 completion 在 prompt**。+304 prompt tok（+45%）来自 4 条示例硬塞进 prompt；completion 仅 +20 tok。每次调用都付一遍这个固定开销。
3. **CoT 在 few-shot 之上再加 +118 prompt tok**（推理要求 + 示例的 reasoning 字段），completion 反而略降（70 vs 74，因为 reasoning 字段挤占了 sub 描述）。
4. **整体准确率不区分 #4/#3**（都是 97.5%），但子维度取舍很不同：
   - #4 的 1 个错样本 q22-010 探店 → #3 修对了（CoT 词义推理生效）
   - #3 的 Q22 互动维度 74.1% vs #4 的 75.3%（基本持平，比早先记录的 -8.7pp 缓和——CoT 副作用波动大）
5. **延迟和 token 不严格线性相关**：#3 的 token 比 #2 多 +11% 但耗时反而 -2%（1573 < 1603ms），可能因 prompt 缓存或网络抖动。生产环境真实延迟应以 P50/P95 为准。

### 成本估算（按百万次调用）

按 GPT-4.1 公开报价（约 $2/M prompt tok、$8/M completion tok）：

| 方法 | 单次成本 | 100 万次成本 | 相对增量 |
|---|---|---|---|
| #4 零样本 | $0.00179 | **$1788** | 基线 |
| #2 +few-shot | $0.00252 | $2518 | +$730（+41%） |
| #3 +few-shot+CoT | $0.00274 | **$2738** | +$950（+53%） |

> 推算：当问卷上线后稳态 QPS 假设 1 QPS、3 字段并行 → 一天 ≈ 26 万次抽取调用。月度成本：#4=$14k、#2=$20k、#3=$22k。**few-shot 月增 $6k 换 sub 字段从 70%→90% 可用，是值得的；CoT 再 +$2k 换 Q22 longtail 修对 1 条不太划算**。

### 工程选型矩阵（修订）

原结论"生产环境推荐 #2"基于精度+速度两轴，加上成本维度后建议细化：

| 场景 | 推荐方法 | 理由 |
|---|---|---|
| 极致省钱（成本敏感型应用、批量离线打标） | **#4 零样本** | 精度天花板已经 97.5%，子标签可用度低 (55%) 但主标签可用 |
| 平衡（生产推荐） | **#2 few-shot** | sub 字段大幅可用，主标签持平，成本 +41% 换 sub 可用度 +20pp |
| 已知 longtail 高发字段（Q22 网络词密集） | **按字段开 CoT**（仅 Q22 加 CoT，Q23/Q24 不加） | 而不是全字段都开 |
| 高预算 + 强解释性需求（PPT demo、可解释性研究） | **#3 +CoT** | reasoning 字段本身有展示价值 |

## Baseline #7：held-out 对照集（同分布偏差第二层验证）— 2026-06-06

**动机**：负责人质疑"GPT-4.1 扩充 + GPT-4.1 评测 = 同分布偏差，结果偏乐观"。第一层（跨模型）已用三家模型在扩充集上的差距 ≤ 3pp 反驳；本第二层用一份**生成源完全不同**（Claude 4.5/4.7 而非 GPT-4.1）+ **100% 人工筛选**+ **刻意拉高 longtail 比例** 的 80 条 held-out 集，回答"换一份分布不同的数据，准确率是否还稳定"。

**数据集**：`eval/q{22,23,24}_holdout.jsonl`（27+27+26 = 80 条），category 分布 25/45/16/14/0（normal/longtail/boundary/perturbation/empty），刻意把 longtail 拉到 45%，详见 `eval/HOLDOUT-README.md` 与 `eval/DATASET-DESIGN.md` §5。

**模型 + 配置**：gpt-4.1 + 零样本（与 baseline #4 同配置，便于直接对比）。

### 错误样本归类（held-out 共 6 条主标签错）

全部集中在 longtail 桶，无 normal/boundary/perturbation 错误：

- Q22：`chill一下`（过于宽泛，标注为空但模型判 stroll，可争议）
- Q23：`全是惊喜地雷`（比喻模糊）/ `敏感得很说啥都炸毛`（情感反应被判为边界）/ `老说我矫情`（贬低被判为边界）
- Q24：`希望他不要油腻`（流行词被判外貌）/ `不要妈宝`（流行词被判独立性而非性格）

### 结论

1. **整体差距 5pp 在可接受区间**——主因不是同分布偏差，而是 held-out 刻意把 longtail 拉到 45%（vs 扩充集 21%），longtail 桶的错误被放大
2. **normal / boundary / perturbation 三类全部 100%**——证明扩充集训出的 prompt 在主流分布上完全稳定
3. **错误全部集中在 longtail，且都是"标注分歧"而非"系统性失败"**——例如"油腻"既可归外貌也可归性格，"chill一下"是否完全空判存在判断空间
4. **互动维度 100%**——证明修正后的"显式信号词才判 strong/weak"规则在异源数据上同样可靠

**对负责人的回复**：扩充集准确率 97.5% 不是"GPT-4.1 自洽"产生的虚高。在 longtail 比例翻倍 + 异源生成 + 100% 人工筛选 三重压力下，主标签准确率仍 92.5%，且失败模式可解释、可分类。同分布偏差在当前数据集规模下被证明可控。
