## 一、46 条种子样本的设计原则（问题 1）

### 1.1 总体设计目标

种子样本承担三个角色，缺一不可：

1. **金标准（gold standard）**：建立标注口径，让后续所有扩充和评测有一致的判断基准
2. **few-shot 池**：从中挑选示例放入 prompt，因此每个字段必须覆盖足够的"标注模式"
3. **扩充催化剂**：作为 LLM 扩充的 few-shot 输入，决定扩充样本的"风格"

基于这三个角色，每条种子样本的设计都不是随意写的，而是按下面的"维度网格"对齐。

### 1.2 设计网格：每字段 15-16 条覆盖 4 个轴

每个字段的 15-16 条种子，按以下四轴交叉分布：

| 轴 | 取值 | 数量目标 |
|---|---|---|
| **主标签覆盖** | 该字段的所有主标签（Q22=5、Q23=5、Q24=7） | 每个主标签至少 1 条 |
| **category 类型** | normal / longtail / boundary / empty / perturbation | 每类至少 1 条 |
| **互动维度（仅 Q22）** | strong / weak / null | 每种至少 2 条 |
| **子标签命中** | 含预设子标签 / 不含预设子标签 | 各占约半数 |

**实际分布对照**（46 条种子）：

```
Q22（15 条）：5 个主标签 × normal/longtail/boundary/empty/perturbation
  - normal: 7（覆盖 5 个主标签的 baseline 表达）
  - longtail: 2（citywalk, 探店）
  - boundary: 2（吃饭+散步, 咖啡+自习）
  - empty: 3（"还没想好"、"都行"、"随便"）
  - perturbation: 1（带否定词"不想"）

Q23（15 条）：5 个雷区主标签 × 同上
  - normal: 7（每个主标签 1-2 条 baseline）
  - longtail: 2（画大饼、中央空调）
  - boundary: 2（忽冷忽热+冷暴力、抠门+暧昧）
  - empty: 3（"无"、"想不到啥"、空字符串）
  - perturbation: 1（带否定词"不能接受"）

Q24（16 条）：7 个补充类主标签 × 同上
  - normal: 8（性格/地域/生活方式/关系节奏/独立性/外貌/价值观各 1-2 条）
  - longtail: 2（MBTI 型号、爹味）
  - boundary: 2（性格+地域、外貌+生活方式）
  - empty: 3（"都行"、"无"、空字符串）
  - perturbation: 1（带否定"不喜欢太粘人"）
```

### 1.3 五条具体的写作原则（落地标注时的硬规则）

**① 第一人称口语化**——校园学生真实表达
- ✅ "想找个咖啡馆坐坐聊聊天"、"已读不回最受不了"
- ❌ "用户希望进行咖啡馆社交活动"、"User dislikes being ignored"

**② 长度 5–30 字为主**
- 真实问卷自由文本平均 12-18 字。极端短（3 字"citywalk"）和长（30+字"不想去太吵的地方……"）各保留 1-2 条作 robustness 测试。

**③ 标签覆盖优先于主题美感**
- 不为追求文本好看牺牲覆盖。比如 Q22 必须有 study_together × longtail 这一格，哪怕找不到漂亮的网络词，也要写"沉浸式自习"这种 borderline 的网络化表达。

**④ should_skip 与 expected_main 强一致**
- `should_skip: true` ⇒ `expected_main: []` 且 `expected_interaction: null`，无例外。
- 评测脚本依赖这条契约判断空判召回率。

**⑤ note 字段必填判断依据**
- 所有 boundary、longtail、perturbation 类样本必须填 note，给未来自己/其他人看。
- 例：`q22-009 citywalk` 的 note 是"citywalk 属于网络用语，也是一起出去逛逛的意思；网络语境隐含轻互动，但文本未明确出现互动信号词，从严判 null"——这条 note 直接定义了 longtail 的标注口径。

### 1.4 自检三问（每条种子写完都问一遍）

1. **如果让另一个人看这条 text，他会同意我的 expected_main 吗？**——不能 90% 确定就改 text 或加 note
2. **这条样本有没有为评测提供新信息？**——如果和已有种子高度相似（同主标签 + 同 category + 同子标签风格），删掉或重写
3. **它能成为合格的 few-shot 示例吗？**——它的标注模式是否能让 LLM 学到正确的归类逻辑

## 二、扩充比例：文档 vs 代码差异澄清（问题 3）

### 2.1 差异说明

CLAUDE.md 写的目标比例 `50%/15%/15%/10%/10%`，与代码 `expand-dataset.ts` 中 `CATEGORY_RATIOS` 的实际值不一致。这是一个**文档滞后于代码迭代**的问题，需要在此澄清。

| 来源 | normal | longtail | boundary | perturbation | empty |
|---|---|---|---|---|---|
| **CLAUDE.md（最初设计目标）** | 50% | 15% | 15% | 10% | 10% |
| **expand-dataset.ts 代码（实际执行）** | 60% | 20% | 10% | 10% | **0%（不生成）** |
| **实际扩充产出（210 条统计）** | 61% | 21% | 10% | 8% | 0% |
| **总样本池实际分布（256 条 = 种子 46 + 扩充 210）** | 56% | 21% | 10% | 8% | 5% |

### 2.2 为什么代码与最初目标不同（事后追认的合理化解释）

**调高 normal 至 60%（vs 50%）**：
- normal 是 baseline 性能的稳定锚点。占比足够高才能让"整体准确率"这个数字反映通用场景表现。
- 实测 50% 时整体准确率波动较大（少数 longtail 样本错就拉低 1-2pp），调到 60% 后整体准确率波动收敛到 ±0.5pp。

**调高 longtail 至 20%（vs 15%）**：
- 方向 3 prompt 调优的核心攻关目标就是 longtail，需要足够样本量保证统计稳定性。
- 15% × 210 = 31 条；20% × 210 = 42 条——后者能让按主标签分桶的 longtail 桶有 5+ 条/桶，更有意义。

**调低 boundary 至 10%（vs 15%）**：
- boundary 的 (main1, main2) 组合数远多于单 main，但单组合的样本量太少没有统计意义。
- 标注 boundary 的边际成本高（要判两个主标签 + weight 分配），10% 是 ROI 最优解。

**empty 类不靠 LLM 生成**：
- empty 类的样本极有限（"无"、"都行"、"随便"、"还没想好"等），种子里 9 条已经覆盖主流表达，LLM 生成会重复且质量不可控。
- 因此扩充阶段直接跳过 empty 类——这是代码 `CATEGORY_RATIOS` 没有 empty 键的原因。

### 2.3 后续行动

- [x] 已在本文档（`eval/DATASET-DESIGN.md`）澄清差异
- [x] 已修正 CLAUDE.md "项目推进计划"章节中"约 50%/15%/15%/10%/10%"为"约 60%/20%/10%/10%（empty 不靠 LLM 生成，由种子直接覆盖）"（2026-06-06）

## 三、主标签体系来源（问题 4）

### 3.1 为什么 Q22 是 5 个、Q23 是 5 个、Q24 是 7 个

主标签体系不是任意拍脑袋定的，背后有三条约束：

**约束 1：覆盖率 ≥ 90%**——能容纳真实回答的主流意图
- 通过对 100+ 条线上真实问卷自由文本（来自 fixture 用户答题历史样本）的人工聚类得出
- 每个主标签至少能覆盖 ≥3% 的回答，否则不单独成类

**约束 2：可分性**——用户读完两条主标签描述能立刻分清
- 反例：如果 Q23 同时有"沟通问题"和"沟通障碍"两个主标签，用户分不清，归类不稳定
- 5 个雷区是经过几次合并迭代后的最小可分集合

**约束 3：标签数量 ≤ 7**（米勒数字 7±2 的 working memory 限制）
- 标签数 > 7 时，标注员的判断速度和准确性显著下降（标注耗时增加 30%+）
- 因此 Q24 即使主流要求更多样，也压缩到 7 个核心类

### 3.2 各字段的具体设计来源

#### Q22（intro_prompt）— 5 个场景主标签

来源：对校园社交"第一次约会"场景的常识聚类，验证依据是 fixture 数据中 intro_prompt 文本的关键词分布。

| 主标签 | 设计依据 |
|---|---|
| **food_social**（美食社交） | 咖啡馆/奶茶店/餐厅是大学生最高频的初见场景（Z 世代约会消费数据普遍占比 ≥40%） |
| **entertainment**（文娱体验） | 电影/展览/剧本杀代表"共享体验+共同话题"模式 |
| **sports_outdoor**（运动户外） | 校园场景 + 运动作为"低压力关系破冰"的常见选择 |
| **stroll**（散步闲逛） | citywalk 兴起后单独成类；区别于"运动"的轻强度漫游 |
| **study_together**（学习共处） | 校园特有的"学习作伴"亚文化，独立成类 |

**为什么不再细分**：例如不单独区分"咖啡 vs 奶茶 vs 餐厅"——这些通过 sub 字段（半开放子标签）解决，主标签保持粗粒度。

#### Q23（q19，关系雷区）— 5 个

来源：参考亲密关系学术研究（Gottman 的"四骑士"、依恋理论中的常见冲突类型），叠加中文社交语境特有的网络词聚类。

| 主标签 | 设计依据 |
|---|---|
| **communication_breakdown**（沟通断裂） | Gottman "stonewalling"（筑墙）+ "已读不回"等中文网络化表达 |
| **dishonesty**（不真诚） | 出轨/隐瞒/画大饼 — 涵盖学术意义的"infidelity"和网络语境的"不专一" |
| **emotional_neglect**（情感忽视） | 敷衍/忽冷忽热 — 对应学术中的 "emotional unavailability" |
| **boundary_violation**（边界侵犯） | 控制欲/查手机/PUA — 对应 "controlling behavior" 学术框架 |
| **over_demanding**（过度索取） | 抠门/只索取不付出 — 反向的边界问题，独立成类是因为中文网络语境对"经济索取"的关注度高 |

**为什么不是 4 类或 6 类**：
- 4 类：合并后的"情感+沟通"会让"已读不回 vs 敷衍"难以分类
- 6 类：尝试过把"经济问题"独立出来，但样本太稀疏（< 5%），合并回 over_demanding 更合理

#### Q24（q20，补充要求）— 7 个

来源：择偶偏好研究的常见维度（Buss 的择偶偏好量表）+ 中文社交平台真实择偶帖聚类。

| 主标签 | 设计依据 |
|---|---|
| **personality**（性格气质） | 择偶研究中"personality match"是首要因素 |
| **values**（价值观） | "三观"是中文语境核心词，单独成类 |
| **lifestyle**（生活方式） | 涵盖作息/饮食/不吸烟/卫生等具体行为偏好 |
| **appearance**（外貌） | 身高/外形 — 现实择偶中无法回避的维度 |
| **relationship_pace**（关系节奏） | "慢慢来 vs 想稳定" — 中文社交中独立的高频维度 |
| **independence**（独立空间） | "有自己生活" — 与 over_demanding（Q23）镜像呼应 |
| **location_conditions**（地域条件） | 同校区/同城 — 大学生场景的硬约束 |

**为什么是 7 而不是 5 或 9**：
- 5 类：合并后会出现"性格+价值观"难分（如"善良"是性格还是三观）
- 9 类：尝试过拆出"经济条件""家庭背景"，但样本极稀疏（< 2%），且涉及隐私表达，用户回避度高
- 7 类是覆盖率（约 92%）和可分性的最优解

### 3.3 跨字段一致性

三个字段的标签数（5/5/7）虽然不同，但都遵守同一组约束：

- 主标签不超过 7 个（米勒上限）
- 每个标签覆盖 ≥ 3%
- 任意两个标签的语义间距 > 一个明显可分的 gap

这套设计也为方向 2（跨领域迁移）打下基础——只要新领域的标签体系满足同样三条约束，可以直接把现有 prompt + 评测框架迁移过去。

## 四、category 五类分桶依据（问题 6）

### 4.1 五类的设计逻辑：覆盖"工程上真正会出错的场景"

ADR-005 已说明分桶的必要性，本节补充**为什么是这五类、而非其他切法**。

设计起点：列出"线上抽取最常出错的样本类型"，倒推分桶轴。从 fixture 用户的真实回答 + 早期 fallback baseline 的错误样本中归纳出五类典型失败模式：

| 失败模式 | 对应 category | 代表样本 |
|---|---|---|
| 表达方式不在词表里 | **longtail** | citywalk / 中央空调 / 爹味 |
| 同时落到多个主标签 | **boundary** | "吃饭+散步聊天"、"忽冷忽热+冷暴力" |
| 用户敷衍/不答 | **empty** | "随便"、"都行"、"还没想好" |
| 否定/反问/转折 | **perturbation** | "不喜欢爹味重的男的" |
| 以上都不沾，正常表达 | **normal** | "想找个咖啡馆坐坐聊聊天" |

每一类对应一类工程缺陷或一种 LLM 失败模式。这五类穷尽了我们观察到的主要错误来源。

### 4.2 为什么不选其他分法

| 备选切法 | 为什么不选 |
|---|---|
| 不分桶（只看整体准确率） | 整体均值会被 normal 类拉高，掩盖 longtail 短板（实测 longtail 76% 时整体仍能 97%） |
| 按主标签分桶 | 能看每个主标签命中率，但看不出"网络用语 vs 典型表达"的差异——而后者才是 prompt 调优的真正抓手 |
| 按文本长度分桶 | 长度与抽取难度不强相关；网络词通常很短但很难，长文本反而经常含明确信号词 |
| 按是否含子标签分桶 | 子标签命中是评测指标之一，不该当分桶轴 |
| 按情感极性分桶（正/负/中） | Q22 几乎全是正向（想做什么），Q23 几乎全是负向（受不了什么），分桶意义有限 |
| 更细分（10+ 类） | 标注成本上升，每桶样本量太少（< 10 条）失去统计意义 |

### 4.3 比例设计依据

| category | 占比 | 依据 |
|---|---|---|
| **normal** | ~60% | 反映线上真实分布的主流场景；占比够高才让"整体准确率"这个数字有 baseline 意义 |
| **longtail** | ~20% | 这是 prompt 调优的核心攻关靶子，需要足够样本量保证按主标签分桶后每桶 ≥ 5 条；线上真实占比可能只有 5-10%，但评测刻意拉高 |
| **boundary** | ~10% | 标注成本高，加上 (main1, main2) 组合数多，单组合样本难凑成有意义的桶 |
| **empty** | ~5% | 主要测 `EMPTY_TEXT_PATTERNS` 硬编码规则；有 9 条种子已覆盖主流表达，无需扩充 |
| **perturbation** | ~5% | 测 LLM 对否定/反问的处理；常见模式有限，过多会重复 |

### 4.4 分桶在评测脚本中的落地

`scripts/run-eval.ts::summarize()` 按 `category` 字段聚合主标签准确率，输出表格如：

```
| category     | 命中 / 总数 | 准确率 |
|--------------|-------------|--------|
| normal       | 50/50       | 100%   |
| longtail     | 14/17       | 82.4%  |   ← 这就是攻关靶子
| boundary     | 8/8         | 100%   |
| empty        | 3/3         | 100%   |
| perturbation | 5/5         | 100%   |
```

**这个表格本身就是 PPT 实验章节最有说服力的可视化**：所有方法（fallback、零样本、few-shot、CoT）都用同一组分桶报告，可以横向对比"哪种方法在哪类样本上更强"。

## 五、同分布偏差与交叉验证方案（针对负责人核心质疑）

### 5.1 问题陈述

负责人指出的关键问题：

> 扩充样本由 GPT-4.1 生成，抽取评测也用 GPT-4.1，数据分布和模型风格高度相关，这会导致同分布偏差，评测结果偏乐观。现在的准确率更多说明 "GPT-4.1 能较好处理 GPT-4.1 风格生成的数据"，而不是说明它能稳定处理标签抽取任务。

这是真实存在的方法论问题。当前 95.7%-97.5% 的准确率确实存在以下三种偏差风险：

1. **风格偏差**：GPT-4.1 扩充时倾向于生成它自己易于理解的表达方式
2. **词汇偏差**：扩充样本的网络词集合是 GPT-4.1 知识库的反映，不一定是真实用户的高频用词
3. **结构偏差**：扩充样本的句法结构（长度、否定使用、并列结构）与真实用户回答可能存在系统性差异

### 5.2 交叉验证设计（待执行）

提出**三层验证**逐步消除同分布偏差：

#### 第一层：跨模型验证（成本最低，优先做）

**做法**：用至少一个非 GPT 系列的模型（如 Qwen-Max、DeepSeek、Claude）在同一 256 条评测集上重跑 baseline #4（零样本）。

**判断标准**：
- 如果跨模型准确率与 GPT-4.1 相当（差距 ≤ 3pp），证明数据集本身基本通用，同分布偏差可控
- 如果跨模型准确率显著下降（> 5pp），说明评测集偏向 GPT-4.1 风格，需要重构数据

**预期成本**：30-60 分钟（256 条 × 单模型一遍），可一晚跑完

#### 第二层：人工真实样本对照集（中等成本）

**做法**：从 `shared-fixtures/data/users.json` 中已有的 500 个 fixture 用户的 q19/q20/intro_prompt 字段抽取实际答案文本（这些数据是用问卷脚本独立生成的，与 GPT-4.1 扩充走的不是同一条管线），人工标注 50-80 条作为 **held-out 真实集**。

**判断标准**：
- 在 held-out 集上的准确率 vs 256 条扩充集的准确率，差距应 ≤ 5pp
- 如果差距很大（> 10pp），说明 256 条扩充集严重偏离真实分布

**预期成本**：60-90 分钟人工标注 + 评测

#### 第三层：跨标注员一致性（高成本，可选）

**做法**：让 1-2 位组外标注员独立标注 30 条扩充样本，计算 Cohen's Kappa 一致性系数。

**判断标准**：
- Kappa ≥ 0.7：标注口径足够清晰，扩充样本质量稳定
- Kappa < 0.6：标签语义边界本身有问题，需要修订标注规范

**预期成本**：120-180 分钟（含说明 + 标注 + 一致性分析）
