# OurAI 问卷自由文本标签抽取

## 固定主标签 + 动态子标签 · 评测驱动 · Prompt 调优

## 一 · 问题背景

**OurAI 问卷有三个开放性文本字段，天然不可计算**

| 字段 | 问题 | 下游用途 |
|---|---|---|
| Q22 `intro_prompt` | 第一次见面，你最希望一起做什么？ | 约会场景匹配 |
| Q23 `q19` | 你受不了对方什么？ | 关系雷区匹配 |
| Q24 `q20` | 对 TA 有什么补充要求？ | 择偶偏好匹配 |

**两种极端方案都走不通**

| 方案 | 问题 |
|---|---|
| 纯关键词规则 | fallback 实测主标签准确率仅 **53.3%**，网络词/否定句/并列结构全漏 |
| 纯开放文本直接入库 | 无法向量化检索，下游匹配推荐无法消费 |

> **选型**：固定主标签（保证可计算）+ 动态子标签（保留语义细节）+ LLM 抽取 + 关键词降级

<!--
53.3%是真实跑过fallback的数字。"中央空调""探店""爹味"这种网络词，规则根本抓不到。纯开放文本又没法给匹配算法消费。所以引出这套方案。
-->

## 二 · 技术方案

**标签体系：三字段各自的主标签设计**

| 字段 | 主标签（数量） | 设计来源 |
|---|---|---|
| Q22 场景 | 5类 + 互动横切维度（强/弱/null） | Z世代约会消费数据 + 校园场景聚类 |
| Q23 雷区 | 5类 | Gottman「四骑士」+ 中文网络词聚类 |
| Q24 补充 | 7类 | Buss 择偶偏好量表 + 中文社交平台真实择偶帖 |

每类主标签挂 2-3 个预设子标签；LLM 可输出词表外的子标签，用 `quote` 字段锚回原文（可解释+可审计）。

**抽取流程**

```
输入文本 → Prompt 构造 → LLM（OpenAI兼容协议）→ 主标签白名单校验 → 输出
                                  ↓ API失败
                             关键词降级（兜底，不崩溃）
```

三个运行时开关：`DATING_TAG_FEW_SHOT=1` / `DATING_TAG_COT=1` / 自动降级

<!--
互动横切维度是Q22特有的，不替代主标签，叠加判断"双人对打/安静陪伴/无信号"。白名单校验保证LLM乱输也不会污染下游。三个开关都是环境变量，不需要重新部署。
-->

## 三 · Prompt 调优 — 实验设计

**攻关目标**：Q23 longtail 桶基线 76.5%（网络词"中央空调/PUA/时间管理大师"分类混乱）

**三组实验**（同一 244 条评测集，剔除 few-shot 样本保证公平）

| 实验 | 配置 | 核心思路 |
|---|---|---|
| **#4 零样本** | 当前 prompt，无额外示例 | 锚点基线 |
| **#2 +few-shot** | 每字段 4 条示例（normal/longtail/boundary/empty 四象限覆盖） | 教格式 + 给网络词范例 |
| **#3 +few-shot+CoT** | 在 #2 基础上加 `reasoning` 字段，要求先翻译词义再选标签 | 让模型显式推理"中央空调→不专一→dishonesty" |

> few-shot ID 硬编码 + `--exclude-few-shot` 标志，确保评测集不包含训练样本

<!--
公平性设计很重要：12条few-shot样本硬编码ID从评测集剔除（256→244），不然#2的准确率会虚高。CoT的核心假设是"让模型先说出语义链再分类"，对词义清晰的网络词应该有效。
-->

---

## 三 · Prompt 调优 — 三轴结果与反直觉发现

| 实验 | 主标签准确率 | 平均耗时 | **Token/样本** | 成本相对基线 |
|---|---|---|---|---|
| **#4 零样本** | **97.5%** | 1464ms | **732** | **基准** |
| #2 +few-shot | 96.7% | 1603ms | 1036 | **+41%** |
| #3 +few-shot+CoT | **97.5%** | 1573ms | 1154 | **+58%** |

> ⚠️ **反直觉发现：零样本最便宜，且与 #3 并列最准**

**为什么 few-shot/CoT 没赢**
- few-shot 把 304 tok 固定堆在每次 prompt，主标签准确率没有对应提升
- CoT 仅修对 2 条 longtail（探店、中央空调），同时让互动维度准确率倒退 8.7pp（注意力分散）
- **few-shot 真正的价值**：子标签命中率 Q22 +19pp（教会模型怎么从原文提炼 sub 字段）

**场景化选型结论**：极致省钱→#4 / 生产平衡→#2 / longtail 高发字段→按字段开 CoT

<!--
加成本这第三轴才看出真相——原来只看精度+速度，差点认定#2是winner。GPT-4.1本身已经吸收了大量分类任务训练数据，多塞4条few-shot是在"教它已经会的事"。调优前先跑零样本基线，别一上来就few-shot+CoT，这是最值得带走的方法论。
-->

## 四 · 评测体系 — 数据集构造

**问题**：评测数据从哪来？人工标注成本太高，直接用生产数据有隐私风险

**三段式方法**（总计 256 条，q22=85 / q23=87 / q24=84）

```
人工种子（46条）  →  GPT-4.1 网格扩充（210条）  →  10% 人工抽检（22条，合格率100%）
```

**关键设计：按 (主标签 × category) 网格调度，强制扩充比例**

| category | 比例 | 目的 |
|---|---|---|
| normal 普通典型 | 60% | 让整体准确率有 baseline 意义 |
| longtail 网络词 | 20% | prompt 调优有足够攻关样本 |
| boundary 双主标签 | 10% | 测试边界判断能力 |
| perturbation 否定/反问 | 10% | 测试语义鲁棒性 |
| empty 敷衍/不答 | 种子覆盖 | LLM 生成的空回答不可信 |

> 不做网格调度时 LLM 偷懒只生成 normal，longtail 样本严重不足

<!--
为什么要网格调度：自由生成时GPT-4.1会全给normal，longtail根本没有足够样本量，prompt调优就无从下手。empty类型有限不靠LLM生成是个坑：LLM生成的空回答往往是"随便写一个短句"，不是真实用户的敷衍模式。
-->

---

## 四 · 评测体系 — 指标 + 同分布偏差双重验证

**4 个核心指标**：主标签准确率 / 子标签宽松命中率 / 互动维度准确率（Q22）/ 空判召回率

---

**同分布偏差质疑**：GPT-4.1 扩充 + GPT-4.1 评测 = 自洽偏乐观？

**第一层：跨模型对照**（同 256 条，换三家模型跑零样本）

| 模型 | 主标签准确率 | 与 GPT-4.1 差距 |
|---|---|---|
| GPT-4.1 | 97.5% | — |
| Claude 4.5/4.7 | ~95-97% | ≤ 3pp |
| Gemini | ~95-97% | ≤ 3pp |

**第二层：held-out 对照集**（80 条，Claude 生成 + 100% 人工筛选，longtail 比例刻意拉到 45%）

| 数据集 | 主标签准确率 |
|---|---|
| 扩充集（256 条，GPT-4.1 生成） | 97.5% |
| **Held-out（80 条，异源+高难度）** | **92.5%** |

6 条错误**全部落在 longtail 桶**，且均为标注分歧（"油腻"归外貌还是性格，人也会争议）；normal / boundary / perturbation 三类全部 100%

> ✅ 同分布偏差在当前规模下可控；97.5% 不是自洽虚高

<!--
held-out三重压力：换生成源、100%人工筛选、longtail比例翻倍。三重压力下还有92.5%，且失败模式可解释。互动维度held-out 100%，证明修正后的"显式信号词才判strong/weak"规则在异源数据上同样可靠。
-->

## 五 · 结论

**核心产出**

| 维度 | 结果 |
|---|---|
| 方案可行性 | 关键词规则 53.3% → LLM零样本 **97.5%**，提升 44pp |
| Prompt 调优 | 零样本已是 Pareto 最优；few-shot 的真实价值在子标签（+19pp），不在主标签 |
| 评测可信度 | 双重验证确认同分布偏差可控，held-out 92.5% 是保守下界 |

**最值得复用的工程资产**

> 评测框架（三段式数据集 + 5类分桶）+ ADR 决策记录 可迁移到任意标签抽取任务

**未来工作**：跨领域迁移（DomainConfig 注入）/ 请求队列+熔断 / 匹配推荐赋能
