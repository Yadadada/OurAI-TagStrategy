P3 / 一、问题与方案

问题背景

三个自由文本字段，天然不可计算

字段内容用途
intro_prompt (Q22)"想做什么活动"第一次约会场景匹配
q19 (Q23)"受不了什么"关系雷区匹配
q20 (Q24)"对 TA 的补充要求"择偶偏好匹配

关键词规则降级 baseline #0：fallback 实测准确率 53.3%——不可生产

三种候选方案对比 → 选「固定主标签 + 半开放子标签」
决策依据：decisions/ADR-003-text-tag-design.md
📝 演讲词

下游算法（人格卡片 / 匹配推荐）需要结构化标签才能消费。最早试过"纯关键词词典"，53.3% 完全不能上线——很多网络词、否定句、并列结构都漏掉。所以引出今天的主题：固定主标签保证可计算，半开放子标签保留语义信息。

P4 / 一、问题与方案

标签体系设计依据

三条硬约束（来源：eval/DATASET-DESIGN.md §3）

  1. 覆盖率 ≥ 90%——能容纳真实回答的主流意图
  2. 可分性——用户读完两条主标签描述能立刻分清
  3. 米勒数字 ≤ 7——超过 7 标注耗时 +30%

各字段的设计来源

字段主标签数设计来源
Q225Z 世代约会消费数据常识聚类 + 校园场景
Q235Gottman「四骑士」+ 中文网络词聚类
Q247Buss 择偶偏好量表 + 中文社交平台真实择偶帖
每个数字背后都有学术依据 + 实测覆盖率验证，不是拍脑袋
📝 演讲词

负责人最关心的问题之一就是"为什么是 5/5/7"。我们写了 DATASET-DESIGN.md 第 3 节专门回答这个问题。Q22 和 Q24 都试过 5 类、6 类、7 类、9 类，最后回到当前体系是因为它在覆盖率和可分性的 ROI 最优。这套约束也为方向 2（跨领域迁移）打下基础。

每个主标签下挂 2-3 个 preset sub，模型可输出预设之外的子标签——用 quote 字段把它锚回原文，可解释 + 可审计。

📝 演讲词

互动维度是 Q22 特有的"横切维度"——不替代主标签，而是叠加判断"双人对抗 / 安静陪伴 / 无信号"三种状态，给下游匹配推荐提供更细粒度。半开放体现在子标签：模型抽出"pickleball"这种预设词表里没有的词时，不丢，挂在对应主标签下。

P6 / 二、抽取实现

抽取流程

flowchart LR A[输入文本] --> B[Prompt 构造] B --> C{API Key?} C -->|有| D[LLM 调用
OpenAI 兼容协议] C -->|无| E[Fallback
关键词匹配] D --> F[JSON 解析] F --> G[校验/裁剪
主标签白名单] G --> H[输出
main/sub/weight/quote/interactionMode] E --> H

三个开关（环境变量控制）

  • DATING_TAG_FEW_SHOT=1 — few-shot 4 例/字段
  • DATING_TAG_COT=1 — 轻量 CoT
  • API 失败 → 自动降级 fallback（modelId='fallback-keyword'）
实现：module-b-portrait/src/textTagExtractor.ts
📝 演讲词

整个流程的关键设计点：① OpenAI 兼容协议——可换任意 LLM proxy ② 主标签白名单校验——LLM 出错也不会污染下游 ③ 三个开关都是运行时可切的，不需要重新部署 ④ fallback 不是"保底差几个数字"，而是"API 挂了系统不崩"。

Case 3 / boundary（双主标签）： city walk 加路边吃点东西

quote 字段把抽取结果锚回原文——出错时能秒定位
📝 演讲词

这三个例子就是评测集里的真实样本。Case 1 展示"主标签 + 半开放子标签 + 互动维度"三件套；Case 2 展示对未在词表内的网络词不丢；Case 3 展示双主标签——后面评测的 boundary 桶就是测这种。quote 字段是最重要的工程设计，下游匹配出错时能直接看是哪段原文导致的判断。

P8 / 三、评测体系

评测数据集构造（三段式）

flowchart LR A[人工种子
46 条] --> B[GPT-4.1 网格扩充
210 条] B --> C[10% 人工抽检
22 条] C --> D[256 条总样本池] A -.-> D
阶段数量关键决策
种子46（Q22=15/Q23=15/Q24=16）四轴网格：主标签 × category × 互动 × 子标签覆盖
扩充210按 (main, category) 网格调度，避免 LLM 偷懒只生成 normal
抽检22（10%）合格率 100%

比例：60/20/10/10/0（normal/longtail/boundary/perturbation/empty）

empty 不靠 LLM 生成，由种子覆盖 — 决策见 ADR-004 + DATASET-DESIGN.md §2
📝 演讲词

负责人评审的另一个关键问题："扩充比例为什么是 60/20/10/10？"答案是：normal 60% 让"整体准确率"这个数字有 baseline 意义；longtail 拉到 20% 让 prompt 调优有足够样本量；boundary 标注成本高、压到 10%；empty 类型有限不靠 LLM 生成。每个数字都在 ADR-004 / ADR-005 里写了为什么。

P9 / 三、评测体系

评测指标 + 5 类分桶

4 个核心指标（评测脚本 scripts/run-eval.ts）

指标含义
主标签准确率抽取主标签 ∈ expected_main 即对
子标签宽松命中率substring 双向匹配
互动维度准确率仅 Q22，三值严格相等
空判召回率should_skip:true 时抽取必须为空

5 类 category 分桶 — 每类对应一种工程缺陷

normal       → baseline 锚点
longtail     → 网络词 / 流行语        ← prompt 调优攻关靶子
boundary     → 双主标签
perturbation → 否定 / 反问 / 转折
empty        → 用户敷衍 / 不答
分桶让"整体均值"不再掩盖短板。决策依据：ADR-005
📝 演讲词

分桶是这套评测最关键的工程设计。如果只看整体平均准确率，longtail 76% 时整体仍能 97%——你完全看不出 longtail 是短板。分桶之后每次 prompt 改动都能直接看到"哪一类的数字在动"，调优就有了具体抓手。这一页是 PPT 里最值得 PM 抄走的方法论。

P10 / 四、Prompt 调优

三轴对比 必讲 ①

公平性保障：4 条/字段 few-shot 例子硬编码 ID + --exclude-few-shot 标志，评测时剔除（256→244）

实验主标签准确率平均耗时平均 token/样本成本相对
#4 零样本97.5%1464ms732基准
#2 +few-shot96.7%1603ms1036+41%
#3 +few-shot+CoT97.5%1573ms1154+58%
精度 / 速度 / 成本三轴同看，结论才不会偏
决策依据：ADR-007（few-shot 公平性）+ ADR-008（三轴选型矩阵）
📝 演讲词

最早只看精度，差点认定 #2 是 winner。后来在抽取层透传 OpenAI usage 字段补齐"成本"这第三轴，才看出真相。这里有个很容易踩的坑：评测时如果不剔除 few-shot 用过的样本，#2 的精度会虚高——所以我们硬编码了 12 条 few-shot ID 加 --exclude-few-shot 标志保证公平。

P11 / 四、Prompt 调优

反直觉发现 + 选型矩阵

⚠️ 关键发现：零样本不是最贵的——它最便宜，且与 #3 并列最准

为什么 few-shot/CoT 没赢

  • few-shot 把 304 tok 固定堆在 prompt（每次调用都付）
  • CoT 在 few-shot 之上再 +118 prompt tok 仅换回 1 条 longtail 修对
  • 全字段开 CoT 对互动维度产生注意力分散副作用

场景化选型矩阵

场景推荐原因
极致省钱#4 零样本732 tok 最低
生产平衡#2 few-shot大部分场景的安全选择
longtail 高发字段按字段开 CoT局部性价比
强解释性 / Demo#3 +CoTreasoning 字段本身有展示价值
📝 演讲词

原本以为 PPT 要给"单一推荐"——后来发现"场景化矩阵"才是正确答案。零样本最便宜且最准这件事颠覆了 prompt 调优的常识，但也很合理——GPT-4.1 本身已经吸收了大量类似分类任务的训练数据，多塞 4 条 few-shot 其实是在"教它已经会的事"。这个发现最值得告诉团队：调优前先跑零样本基线，别一上来就 few-shot+CoT。

P12 / 五、同分布偏差应对

第一层：跨模型对照 必讲 ②

质疑：GPT-4.1 扩充 + GPT-4.1 评测 = 同分布偏差，结果偏乐观？

第一层验证：跨模型对照——同一 256 条评测集，三家不同模型重跑零样本

模型主标签准确率与 GPT-4.1 差距
GPT-4.197.5%—
Claude (4.5/4.7)~95-97%≤ 3pp
Gemini~95-97%≤ 3pp
三家差距 ≤ 3pp → 数据集本身基本通用，不是 GPT-4.1 自洽
来源：eval/CROSS-MODEL-RESULT.md
📝 演讲词

负责人在第一阶段评审时直接质疑同分布偏差——这是个真问题。如果只用 GPT-4.1 评测自己生成的数据，97.5% 可能是"虚高"。所以做了三层验证。第一层最便宜也最有说服力：同样的数据换不同 LLM 跑，差距 ≤ 3pp 说明评测集本身就是通用的，不是 GPT-4.1 偏爱自己生成的样本。

P13 / 五、同分布偏差应对

第二层：held-out 异源对照集

80 条 held-out：Claude 生成 + 100% 人工筛选，longtail 比例从 21% 拉到 45%

数据集主标签准确率互动维度
扩充集 #4（256 条）97.5%≥99%
Held-out（80 条）92.5%100%

6 条错误样本全部落在 longtail 桶

chill 一下 · 油腻 · 妈宝 · 炸毛 · 惊喜地雷 · 老说我矫情
→ 都是标注分歧，非系统性失败

normal / boundary / perturbation 三类全部 100% — 主流分布上完全稳定

✅ 同分布偏差在当前规模下被证明可控
来源：eval/HOLDOUT-README.md + BASELINE.md Baseline #7
📝 演讲词

第二层比第一层强：换生成源（Claude 而非 GPT-4.1）、100% 人工筛选、刻意把难度最高的 longtail 比例翻倍。三重压力下还有 92.5%，且 6 条错全部是"边界判断分歧"。比如"油腻"既可归外貌也可归性格，这种分歧人都吵不清楚，不能算系统性失败。互动维度 100% 进一步证明修正后的"显式信号词才判 strong/weak"规则在异源数据上同样可靠。
