# ADR-004: 评测数据集构造方法 — 人工种子 + LLM 扩充 + 10% 人工抽检

**状态**：已实施
**日期**：2026-05-22
**决策者**：项目组

## 背景

方向 1 要求建立可量化的评测框架。评测数据集是其基础，但纯人工标注 200+ 条样本成本高（按每条 2-3 分钟估算 ≈ 8-10 小时人工），纯 LLM 生成又有质量隐患。需要一套兼顾质量、成本、速度的数据集构造方法。

## 决策

采用**三段式数据集构造法**：人工种子 → LLM 扩充 → 人工抽检兜底。

### 流程

1. **人工标注种子（46 条）**：每个字段 15-16 条，由项目组成员按统一标注规范手工写。目标是建立"标注金标准"——保证标签语义边界、weight 分配、网络词归属等关键判断口径一致。
2. **LLM 扩充（210 条）**：用 GPT-4.1 + few-shot（从种子集随机抽取）+ (主标签, category) 网格调度生成新样本。每字段约 70 条，覆盖原种子未充分覆盖的边界情况。
3. **人工抽检 10%（22 条）**：从扩充样本中随机抽 10% 人工核对，要求合格率 ≥ 95%。不达标则回炉重新生成或调整 prompt。

### 关键参数

| 项目 | 数值 | 理由 |
|---|---|---|
| 种子样本规模 | 46 条 | 既能为 LLM 扩充提供足够 few-shot，又不过度消耗人工成本 |
| 扩充倍率 | ~5x（46→256） | 经验值，超过 10x 后 LLM 输出会出现明显模式化重复 |
| 抽检比例 | 10% | 行业惯例，统计学上 22 条样本足以暴露系统性质量问题 |
| 抽检合格率阈值 | ≥ 95% | 实测达 100%，证明方法有效 |
| 扩充模型 | GPT-4.1 | 与抽取阶段同模型，避免 train/test 域偏差 |

### 抽检判定规则

抽检时核对三项：
1. `expected_main` 是否合理（按 `tagTree.ts` 的标签语义判断）
2. `text` 是否符合中国大学生口语表达（不是 LLM 翻译腔）
3. `category` 标注是否准确（normal/longtail/boundary/empty/perturbation 归类）

任一不符即记为不合格。

## 为什么不选其他方案

- **纯人工标注（200+ 条）**：成本 8-10 小时，且单人标注容易疲劳后口径漂移
- **纯 LLM 生成（无种子）**：LLM 没有金标准会自由发挥，归类标准不一致
- **纯 LLM 生成（有种子但不抽检）**：质量不可验证，下游评测数字失去参考价值
- **付费众包平台**：本项目预算/时间不允许，且众包标注员对"网络用语"的归类反而不如项目组准确

## 实现文件

| 文件 | 职责 |
|---|---|
| `eval/q{22,23,24}_seeds.jsonl` | 46 条人工种子 |
| `eval/q{22,23,24}_expanded.jsonl` | 210 条 LLM 扩充 |
| `scripts/expand-eval-data.ts` | 扩充脚本（GPT-4.1 + few-shot + 网格调度 + 去重） |
| `eval/audit/{field}-{timestamp}.md` | 抽检记录（22 条核对结果） |

## 后果

- **总样本池 256 条**（种子 46 + 扩充 210），按字段分布 q22=85 / q23=87 / q24=84
- 扩充耗时约 30 分钟（含人工抽检），相比纯人工节省约 80% 时间
- 抽检合格率 ≈ 100%，下游 baseline 数字（97.5%）有可信支撑
- 此方法可复用：未来加新主标签或新字段时，按同一流程低成本扩充
