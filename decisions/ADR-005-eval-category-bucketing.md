# ADR-005: 评测数据集分桶规范 — 五类 category 覆盖

**状态**：已实施
**日期**：2026-05-31
**决策者**：项目组

## 背景

评测数据集如果只有"普通典型样本"，整体准确率会被拉到虚高（97%+），但无法暴露真实问题——网络用语、多标签边界、空回答、扰动文本这些场景才是工程上真正会出错的地方。需要一套能定位短板的分桶规范。

## 决策

将每条样本标注 `category` 字段，分为 **5 类**，评测脚本按 category 分桶报告主标签准确率，定位短板。

### 五类定义

| category | 含义 | 目标占比 | 典型例子 |
|---|---|---|---|
| **normal** | 典型表达，预设子标签正面命中 | ~50% | "想找个咖啡馆坐坐聊聊天"、"已读不回最受不了" |
| **longtail** | 网络用语 / 隐喻 / 流行语 | ~15% | "citywalk"、"画大饼"、"爹味"、"中央空调"、"PUA"、"探店" |
| **boundary** | 多主标签并列 / 跨类别表达 | ~15% | "一起吃饭，吃完散步聊聊天"（food_social + stroll）、"忽冷忽热，吵架还冷暴力"（emotional_neglect + communication_breakdown） |
| **empty** | 无意义回答 / 空判 | ~10% | "没有"、"无"、"不知道"、"都行"、"随便" |
| **perturbation** | 错别字 / 口语化扰动 / 标点缺失 | ~10% | "想找个嘎啡馆做做"、"已读不回～最受不了" |

### 扩充时的 (主标签, category) 网格调度

LLM 扩充不是自由生成，而是按 (主标签, category) 网格逐格调度，例如：
- 给 `food_social × longtail` 生成 N 条 → 强制 LLM 产出"美食社交主标签 + 网络用语表达"
- 给 `dishonesty × boundary` 生成 N 条 → 强制产出"不真诚 + 与其他主标签共现"

这确保扩充后每个网格至少有几条样本，避免 LLM 偷懒只生成 normal 类。

### 评测脚本按 category 分桶

`scripts/run-eval.ts` 的 `summarize()` 函数按 category 聚合主标签准确率，输出表格如：

| category | 命中 / 总数 | 准确率 |
|---|---|---|
| normal | 50/51 | 98.0% |
| longtail | **14/16** | **87.5%** |
| boundary | 8/8 | 100% |
| empty | 2/2 | 100% |
| perturbation | 6/6 | 100% |

**整体准确率 96.7% 看起来很好，但 longtail 只有 87.5%**——分桶后立刻暴露问题，否则会被 normal 拉高的均值掩盖。

## 为什么不选其他方案

- **不分桶（只看整体准确率）**：均值会被 normal 类拉高，longtail 短板被掩盖
- **按主标签分桶（按 food_social / personality 等分）**：能看每个主标签的命中率，但看不出"网络用语 vs 典型表达"的差异
- **更细分桶（10+ 类）**：标注成本上升，统计意义反而下降（每桶样本太少）

## 实现文件

| 文件 | 职责 |
|---|---|
| `eval/q{22,23,24}_seeds.jsonl` | 每条样本带 `category` 字段 |
| `scripts/run-eval.ts` | `summarize()` 按 category 分桶 + 表格输出 |
| `scripts/expand-eval-data.ts` | (主标签, category) 网格调度生成 |

## 后果

- **定位短板**：所有 baseline 都暴露 longtail 是唯一短板（其他四类都接近 100%），直接指明方向 3 prompt 调优的攻关目标
- **可对比**：所有方法（fallback / 零样本 / few-shot / CoT）都用同一分桶报告，可以横向对比"哪种方法在哪类样本上更强"
- **PPT 叙事**：分桶表格本身就是最有说服力的可视化材料
